# remediaSOAR

Jamf Security Orchestration, Automation and Response on the go!

Available for download on [Apple's App Store](https://apps.apple.com/app/remediasoar/id6692309693).

&nbsp;

## Description

The remediaSOAR app gives administrators a streamlined way to view, filter, and flag macOS security alerts generated by Jamf Protect. You can review detailed data for each detection and take action through integrations with Jamf Pro and Jamf Security Cloud.

With the Jamf Pro integration, you can assign a device to a static computer group to scope a remediation policy, or send a Remote Lock command. 

With the Jamf Security Cloud integration, you can override a device’s risk score to restrict access to sensitive resources.

## Setup Instructions

Jamf Protect and Jamf Pro connect through one of two methods. Choose the method at the top of Settings:

* **Platform**: one API client for the Jamf Platform API Gateway reaches Jamf Protect and, when it is available, Jamf Pro. This is the default for a new installation.
* **Classic**: separate credentials for Jamf Protect and Jamf Pro, as in earlier versions of the app. Existing installations keep using Classic until Jamf Protect is saved under Platform.

Choosing a method only changes which setup screens are shown. The method in use changes when you save Jamf Protect (Platform) or the Jamf Protect credentials (Classic), and Settings marks the active one. If another method is already in use, the app asks you to confirm the switch first. Jamf Security Cloud has its own credentials under either method.

### Platform Gateway

A Jamf Account administrator creates the API integration. In Settings, open **Configure Platform Gateway** and select **Permissions & Setup** to see this list in the app. **Copy Guide** and **Share Guide** send it to the administrator.

*Step 1: Create an API Integration*

* In Jamf Account, create an API integration at Platform environment scope for your region

*Step 2: Authorize the Capabilities*

* Endpoint Security
  * Threat Alerts: Read and Update
  * Detection Analytics: Read
* Inventory
  * Devices: Read
  * Device Groups: Read and Update
* Destructive Device Actions
  * Device Lock: Execute

Exact permission names may vary. The Endpoint Security capabilities are required for Jamf Protect. The Inventory and Device Lock capabilities are only used for Jamf Pro, and Device Lock is optional.

*Step 3: Enter the Details in remediaSOAR*

* From Integration details, copy the Environment ID, Client ID, and Client Secret
* In Settings, choose **Platform** and open **Configure Platform Gateway**
* Choose the Region of the integration (United States, Europe, or Asia Pacific)
* Enter the Environment ID, Client ID, and Client Secret
* Optionally, enter text in **Filter Static Groups** so only static computer groups whose names start with it are offered
* Select **Save**

Save tests the connection to Jamf Protect and then to Jamf Pro. Nothing is saved if the Jamf Protect test fails. Jamf Pro does not need to be set up separately, because the app detects whether it is available on every Save and shows the result as **Available**, **Not found in this environment**, or **Not available**. If Jamf Pro is missing or not permitted, Jamf Protect is still saved, the Jamf Pro features stay off, and a note explains why. Fix the permissions, then Save again.

When Jamf Protect runs on Platform Gateway and Classic credentials are still saved, the screen offers **Remove Legacy Credentials**. This deletes the Classic Jamf Protect and Jamf Pro credentials from the device and, through iCloud Keychain, from your other devices. Jamf Security Cloud is not affected.

### Classic

Choose **Classic** in Settings to configure Jamf Protect and Jamf Pro with separate credentials. The sections below describe each one.

### Jamf Protect
Jamf Protect connection information is required to use the application. This integration allows admins to review Alerts with their associated Analytics and Computer details, and update the Alert Status. With the Platform method, the Platform Gateway steps above replace this section.

*Step 1: Create an API Role*

* Navigate to Administrative > Account > Roles
* Create a new Role with the following permissions
  * Computers: Read
  * Alerts: Write & Read
  * Analytics: Read

*Step 2: Create an API Client*

* Navigate to Administrative > API Clients
* Click "Create API Client"
* Type a name for the access (eg. "Mobile Access")
* Assign the Role created in step 1


### Jamf Pro

The optional Jamf Pro integration allows admins to assign a computer to a Static Computer Group and send a Remote Lock command. With the Platform method, Jamf Pro is included in the Platform Gateway steps above and this section does not apply.

* Navigate to Settings > User Accounts and Groups
* Create a new User with a Custom Privilege Set
* Enable only the following permissions: 
  * Jamf Pro Server Objects > Computers: Read & Update
  * Jamf Pro Server Objects > Static Computer Groups: Read & Update
  * Jamf Pro Server Actions > Send Computer Remote Lock Command
  * Jamf Pro Server Actions > Send MDM Check In Command
  * Jamf Pro Server Actions > View MDM command info in Jamf Pro API

### Jamf Security Cloud

The optional Jamf Security Cloud integration allows admins to assign or override the Risk Score for a computer. It uses its own credentials with either connection method.

* Navigate to Integrations > Risk API
* Select Generate API Key
* Name the API key and save the credentials

## Using the app

Once the settings have been configured, you can use the filter button to view security alerts by severity and date range. You can swipe left or right on alert items to resolve or flag them for followup. Tapping an alert item will display extended details. If you've configured the Jamf Pro or Security Cloud integrations, you can use the actions button in the upper-right to lock the device, add it to a static group to trigger a remediation workflow, or update the security cloud risk score to limit access to sensitive resources. 

&nbsp;

## Securing Your Secrets

Server URLs, Environment IDs, Client and User IDs, Client Secrets, and Passwords are stored in Keychain. If you enter them once and you use iCloud keychain sync, the information will already be available when you run the app on other devices using the same Apple ID.
